# v5 Channel: One Edit Channel (UC)

Status: adopted 2026-08-26. `UC` rules are normative. Semantics of the surviving channel are owned by `spec-better-ai/01-edit-channel.md` (`EC1`–`EC20`); this document owns the teardown of the coexistence those rules were written inside and the final shape of the routing brain. Where a UC rule and an EC rule appear to conflict, the EC rule wins and the UC rule must be amended — with one exception: `EC12` (the coexistence flag) is fulfilled and retired by UC1, and is amended with a dated correction in the same PR.

## 1. The Channel

- UC1. **The tool channel is the only edit channel, and the coexistence is torn down, not switched off.** Every durable AI document mutation originates as an `edit_document` tool call. The `<pen-fast-apply>` XML contract is deleted from the tree: the stream parser, the closing pass, the `text-fast-apply` and `markdown-fast-apply` strategies, and the `markdown-full-replace` escape all go, together with their tests and prompt scaffolding. The `editChannel` option, the `AIEditChannel` union, and `AI_EDIT_CHANNELS` (`runtime/contracts.ts:70`) are removed — a host that sets `editChannel` gets a compile error, not a silently ignored knob. Presets, playground, examples, and docs move in the same release (`05-phases.md`, Wave 1). Keeping the loser dark was considered and rejected: dark code still costs its tests, its amendments, and every reader who must learn why it exists (`00-concept.md` §7 decision 1).
- UC2. **No mutation is ever derived from assistant text, and no failure is ever an edit.** `EC1`'s fence becomes unconditional: text deltas exist only for watched generation into streaming targets (`openTextStream` — continuation and selection rewrite), never as an edit plan. The plain-markdown fallback — which today can answer an XML parse failure by applying an unasked-for full-document replace — is deleted with its channel. A parse-shaped or schema-shaped failure surfaces as a `diagnostic` event and a refusal result; the regression test that pins this must construct the malformed-payload case and assert the document hash is unchanged.
- UC3. **The structured planner lane is deleted.** `runtime/structuredPlanner/`, `runtime/planExecutor/`, and `runtime/planValidation/` (2,847 lines, 12 files at adoption) exist to serve the legacy generation path; the planner's own kind gate cannot emit the lane's flagship op for primary edits (`structuredPlanner/parse.ts`, `resolveAllowedPlanKinds`). They are deleted with their barrel exports. Fence: anything the review lane or local-operation execution provably still needs is extracted first as a named module with its own tests, and the extraction PR lists what moved and its consumer — an extraction without a consumer is a keep in disguise (WA9).
- UC4. **One staleness authority.** Working-set view fingerprints (`runtime/viewHashes.ts`, per `EC7`/`EC9`) are the only gate a mutating tool consults. The per-block revision counter (`getBlockRevision`) is deleted from edit gating and from the tool payloads; if working-set refresh still needs a change signal it subscribes to commit events. Two authorities that can disagree about "stale" is the defect; the fingerprint — which hashes what the model was actually shown — is the one that matches the channel's addressing model.

## 2. The Brain

- UC5. **The route vocabulary shrinks to the reachable set, and reachability is proved, not asserted.** After the teardown, every union member in `runtime/contracts.ts` must have a production consumer or it is deleted: `AIApplyStrategy` and `AIEditChannel` disappear entirely; `AIPlannerMode` and the planner-only members of `AIStructuredLane` go with UC3; `AIMutationMode` keeps only members a route can still produce. The 15-union vocabulary (1,600 nominal route shapes at adoption) must fold to: prompt intent, route lane, mutation preference, and target kind. The router keeps a property test: for every classifiable input in the corpus, exactly one route resolves, and every union member is produced by at least one corpus entry — a member no corpus entry produces fails the test and gets deleted.
- UC6. **The loop runs tools; tools own their payloads; the controller owns sessions.** `agentic/loop.ts` may know that a mutating tool exists and must be forced when an edit is owed (`EC17`); it may not encode any tool's payload shape. The `edit_document` refusal payload, retry shaping, and fingerprint echo live with the tool executor (`runtime/` / document-ops side), not in the loop. At adoption the loop is 737 lines with `edit_document` shape knowledge inlined (`loop.ts:719` names the tool; the retry shaping around it knows the ops array); after Wave 3 the loop's knowledge of the tool is its name and the forcing rule. This is the boundary that keeps the next tool from growing the loop again.
- UC7. **Reads stay plural; in-editor writes stay singular.** The in-editor loop mounts read tools plus exactly one mutating tool (`edit_document`). The single-purpose mutating tools (`insert_block`, `update_block`, `delete_block`, `move_block`, `write_document`) remain in `@input/pen-document-ops` as the external tool-server contract — skills-lane agents and MCP-style hosts keep them — and must not be mounted into the in-editor loop. The document-ops README states which surface each tool serves. A tool that serves neither surface is deleted (inventory rule, WA9).
- UC8. **Question intent never touches mutation plumbing.** A prompt classified as a question about the document is answered from reads; it must not open a review session, stage a suggestion surface, or force a mutating tool. The claiming test asks a question against a fixture document and asserts zero staged suggestions, zero review sessions, and an unchanged document hash — while the same fixture under an edit prompt produces a staged edit, so the test cannot pass by the channel being broken.
- UC9. **The teardown is one coordinated release.** All UC deletions ship in the same 0.5 minor with one migration note covering: `editChannel` removal, strategy/planner export removal, fallback removal, and the staleness change. Per API7 there is no deprecation window; hosts that need the XML channel pin the previous minor. A partial teardown that ships some deletions and defers others past the release boundary fails this rule (WA11).

## 3. Testing Contract

Claiming tests carry the rule ID in the test name (coverage posture: reported until claimed, per `README.md`).

- UC1: an extension-construction test asserting the AI extension exposes no `editChannel` option and mounts the tool channel unconditionally; plus a grep gate that `pen-fast-apply` survives nowhere in `packages/` source.
- UC2: the malformed-payload regression (document hash unchanged, diagnostic emitted); plus deletion of the fallback's own tests with the fallback.
- UC3: barrel-export test asserting planner symbols are gone from `@input/pen-ai`'s public API (api-report regen is the gate's artifact).
- UC4: the fingerprint tests already claiming `EC7`/`EC9` remain the authority; add one asserting no code path consults `getBlockRevision` for edit gating (grep gate on the ai package).
- UC5: the router property test over the corpus (every input → exactly one route; every union member produced at least once).
- UC6: a loop test asserting the loop's tool-forcing decision carries only the tool name; payload-shape assertions live in tool-executor tests.
- UC7: tool-server test asserting the in-editor mount list is reads + `edit_document`; document-ops tests keep covering the host-facing tools.
- UC8: the question-intent test described in the rule.
- UC9: release-mechanics, verified by the Wave 3 exit gates (changeset present, migration note present, one version bump).
