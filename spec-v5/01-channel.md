# v5 Channel: One Edit Channel (UC)

Status: adopted 2026-08-26. Amended 2026-08-26 after Wave 1 shipped (commit `bdcf4ec`, 129 files, 1,984 insertions, 5,311 deletions, 23 files deleted): UC1 corrected on which strategies survive, UC3 corrected on what the planner lane is and why it must go. Amended again 2026-08-26 after UC3's first half shipped out of order (18 files, 1,438 deletions): the text-parsed plan door is closed, so UC2 now holds unconditionally, and the structured-preview surface is measured as producer-less — evidence Wave 2 inherits. `UC` rules are normative. Semantics of the surviving channel are owned by `spec/packages/extensions/ai.md` (`EC1`–`EC20`); this document owns the teardown of the coexistence those rules were written inside and the final shape of the routing brain. Where a UC rule and an EC rule appear to conflict, the EC rule wins and the UC rule must be amended — with one exception: `EC12` (the coexistence flag) is fulfilled and retired by UC1, and is amended with a dated correction in the same PR.

## 1. The Channel

- UC1. **The tool channel is the only edit channel, and the coexistence is torn down, not switched off.** Every durable AI document mutation originates as an `edit_document` tool call. The `<pen-fast-apply>` XML contract is deleted from the tree: the stream parser, the closing pass, the `markdown-fast-apply` strategy and its `markdownFastApply` / `markdownPatchPlan` runtime, the `markdownFastApplyMethods` controller bag, the plain-markdown fallback, and the `context-first` lane, together with their tests and prompt scaffolding. The `editChannel` option, the `AIEditChannel` union, and `AI_EDIT_CHANNELS` are removed — a host that sets `editChannel` gets a compile error, not a silently ignored knob. Presets, playground, examples, and docs move in the same release (`05-phases.md`, Wave 1). Keeping the loser dark was considered and rejected: dark code still costs its tests, its amendments, and every reader who must learn why it exists (`00-concept.md` §7 decision 1).
  - **Correction, 2026-08-26 (shipped).** UC1 as adopted also ordered `text-fast-apply` and `markdown-full-replace` deleted. That was wrong: neither is an XML contract. `resolveApplyStrategy` hands `text-fast-apply` to the streaming lanes (selection rewrite, and cursor continuation when the content format is text) and `markdown-full-replace` to the non-tool markdown lanes (buffered block generation, review). They are generation-into-a-target strategies, which EC1 explicitly permits, so they survive. What they carry instead is a naming defect: both are named after the channel that no longer exists, and `fast-apply` now denotes nothing in the tree. They are renamed to describe what they do, in Wave 3 with the rest of the vocabulary fold (UC5) — a name that contradicts the architecture is a permanent reader tax, not a matter of taste (v4 `05-structure.md` CS4 sets the precedent).
  - **Correction, 2026-08-26 (shipped).** The literal token `pen-fast-apply` survives in exactly one place: a negative test that feeds the old XML into the stream and asserts the document does not change. That test is UC2's evidence and is kept deliberately; GATE 1.4 is amended to allow that single population.
- UC2. **No mutation is ever derived from assistant text, and no failure is ever an edit.** `EC1`'s fence becomes unconditional: text deltas exist only for watched generation into streaming targets (`openTextStream` — continuation and selection rewrite), never as an edit plan. The plain-markdown fallback — which today can answer an XML parse failure by applying an unasked-for full-document replace — is deleted with its channel. A parse-shaped or schema-shaped failure surfaces as a `diagnostic` event and a refusal result; the regression test that pins this must construct the malformed-payload case and assert the document hash is unchanged.
- UC3. **The structured planner lane is deleted, because it is the second text-parsed edit channel.** `runtime/structuredPlanner/`, `runtime/planExecutor/`, and `runtime/planValidation/` measure **4,279 lines across 22 files** (2026-08-26; the adoption-day figure of 2,847 undercounted by missing the entry modules and the planner's own tests). They are deleted with their barrel exports. Fence: anything the review lane or local-operation execution provably still needs is extracted first as a named module with its own tests, and the extraction PR lists what moved and its consumer — an extraction without a consumer is a keep in disguise (WA9).
  - **Correction, 2026-08-26 (measured).** UC3 as adopted justified the deletion as dead weight whose flagship op was unreachable. The real reason is worse and makes UC3 the highest-priority rule in this document. The planner receives its plan as a **`text-delta` payload that the runtime parses into ops** — the model emits JSON in the assistant text stream, `parseStructuredPlanPreview` / the plan validator turn it into a mutation, and it lands as a suggestion. That is a durable mutation derived from assistant text, which is exactly what UC2 and `EC1` forbid. **Wave 1 deleted one text-parsed edit channel and left another standing.** Evidence: `extension.part13.test.ts` ("executes review-safe block convert plans through the existing suggestion path") streams a JSON `block_convert` plan as `text-delta` and asserts `planState: "validated"` plus a staged conversion; `extension.part8.test.ts` does the same for streamed structured previews.
  - **Correction, 2026-08-26 (measured).** The two doors into the planner are now known. `reconcilePlannerModeWithPrompt` (`runtime/router.ts`) demotes `structured` to `text` for every flow-markdown route **except review intent**, so the live doors are (a) `intent === "review"`, and (b) block targets whose resolved content format is not markdown. Both land on the `tool-loop` lane after Wave 1 deleted `context-first`, which means a route can carry `applyStrategy: "tool-edit"` and `plannerMode: "structured"` at the same time — the edit tool mounted and a text-parsed plan requested in one prompt.
  - **Correction, 2026-08-26 (measured).** `planExecutor` is load-bearing beyond the planner: `controller/reviewResolutionMethods.ts` and `controller/generationExecutionFinalize.ts` both import `buildDocumentMutationPlanExecution`. The UC3 fence is therefore proven, not hypothetical — the executor is extracted before the planner is deleted.
  - **Do not attempt this opportunistically.** Forcing `plannerMode` to `"text"` on the tool-loop lane was tried on 2026-08-26 and reverted: it is a three-line change that types and lints clean, and it breaks both live paths above (2 failing tests) because it removes the mechanism without providing the replacement. The replacement exists — `EC18`'s `set_block_props` already expresses `block_convert`, and `format_text` covers the mark plans — so UC3 is a migration followed by a deletion, executed in Wave 3 behind the corpus net, in this order: migrate the block-plan paths onto `edit_document`, extract the executor for review resolution, then delete planner, validation, and the `plannerMode` vocabulary together.
  - **Correction, 2026-08-26 (shipped, first half).** The text-parsed door is closed. `runtime/structuredPlanner/` and its barrel are deleted with the three functions that formed the door — `buildPlannerPrompt` (asked the model for JSON), `parseStructuredPlanPreview` (parsed half-arrived JSON out of `text-delta`), and `parseStructuredPlanResult` (parsed the final text into a plan) — and the `plannerMode` vocabulary is gone from the router, `runtime/contracts.ts`, `runtime/blockAdapters.ts`, the controller debug state, and the public API (`AIPlannerMode`, `AI_PLANNER_MODES`). Measured: 18 files, 31 insertions, 1,438 deletions, 7 files deleted, against 125 lines of new code (`runtime/generationTarget.ts`, which holds the three target/mode helpers that outlived the planner, plus the reachability test). `pnpm typecheck` clean; `@input/pen-ai` 499 tests and `@input/pen-react` 492 tests green.
  - **The migration landed as specified.** `extension.part13.test.ts` now drives block conversion through an `edit_document` `set_block_props` call and asserts the same staged-then-accepted outcome it asserted through the JSON plan. That is UC3's replacement claim tested, not asserted.
  - **The fence held, and it is now a fence around unreachable code.** `runtime/planExecutor/` (7 files, 1,323 lines) and `runtime/planValidation/` (3 files, 856 lines) survive because `controller/reviewResolutionMethods.ts` and `controller/generationExecutionFinalize.ts` import `buildDocumentMutationPlanExecution` to resolve already-staged review items. Nothing can hand them a plan from a text stream any more; they execute plans that the review lane already holds.
  - **One capability was removed, not migrated.** Previews of a partially-arrived plan are gone (`extension.part8.test.ts`'s streaming-preview case, and its React mirror `aiPrimitives.25.test.tsx`, 359 lines). That preview existed only because half-written JSON can be re-parsed on every delta; a tool call arrives complete, so the capability has no expression on the surviving channel. Staged edits still surface through suggestions. Recorded in the changeset as a behavior removal.
  - **Consequence for Wave 2 (measured, unshipped).** With the door closed, the structured-preview surface has **zero reachable producers**. The one remaining producer is `onStructuredData` in `controller/generationExecutionLoop.ts`, gated on `useStructuredIntentTransport`; `__tests__/uc3.planReachability.test.ts` proves that flag is always false, because every registered block adapter carries `transportKind: "flow-text"` and adapter resolution cannot yield anything else. Everything downstream of it — `Pen.AI.Progress`'s `data-structured-preview-*` attributes, `primitives/ai/structuredTargetPreview.tsx`, `hooks/useAIStructuredPreview.ts`, `utils/structuredPreview.ts`, and the preview-patch/equality helpers — is now dead weight that Wave 2 deletes with the rest of the preview surfaces (RS rules). Do not add a producer to keep it alive.
- UC4. **One staleness authority.** Working-set view fingerprints (`runtime/viewHashes.ts`, per `EC7`/`EC9`) are the only gate a mutating tool consults. The per-block revision counter (`getBlockRevision`) is deleted from edit gating and from the tool payloads; if working-set refresh still needs a change signal it subscribes to commit events. Two authorities that can disagree about "stale" is the defect; the fingerprint — which hashes what the model was actually shown — is the one that matches the channel's addressing model.

## 2. The Brain

- UC5. **The route vocabulary shrinks to the reachable set, names included, and reachability is proved, not asserted.** Names that refer to the deleted channel are renamed in this fold: the `text-fast-apply` and `markdown-full-replace` strategies (to names describing streaming generation), `controller/fastApplySupportMethods.ts`, and its `ai-markdown-fast-apply` telemetry surfaces. A telemetry surface name is a wire-visible string, so its rename ships with the release note. After the teardown, every union member in `runtime/contracts.ts` must have a production consumer or it is deleted: `AIApplyStrategy` and `AIEditChannel` disappear entirely; `AIPlannerMode` and the planner-only members of `AIStructuredLane` go with UC3; `AIMutationMode` keeps only members a route can still produce. The 15-union vocabulary (1,600 nominal route shapes at adoption) must fold to: prompt intent, route lane, mutation preference, and target kind. The router keeps a property test: for every classifiable input in the corpus, exactly one route resolves, and every union member is produced by at least one corpus entry — a member no corpus entry produces fails the test and gets deleted.
- UC6. **The loop runs tools; tools own their payloads; the controller owns sessions.** `agentic/loop.ts` may know that a mutating tool exists and must be forced when an edit is owed (`EC17`); it may not encode any tool's payload shape. The `edit_document` refusal payload, retry shaping, and fingerprint echo live with the tool executor (`runtime/` / document-ops side), not in the loop. At adoption the loop is 737 lines with `edit_document` shape knowledge inlined (`loop.ts:719` names the tool; the retry shaping around it knows the ops array); after Wave 3 the loop's knowledge of the tool is its name and the forcing rule. This is the boundary that keeps the next tool from growing the loop again.
- UC7. **Reads stay plural; in-editor writes stay singular.** The in-editor loop mounts read tools plus exactly one mutating tool (`edit_document`). The single-purpose mutating tools (`insert_block`, `update_block`, `delete_block`, `move_block`, `write_document`) remain in `@input/pen-document-ops` as the external tool-server contract — skills-lane agents and MCP-style hosts keep them — and must not be mounted into the in-editor loop. The document-ops README states which surface each tool serves. A tool that serves neither surface is deleted (inventory rule, WA9).
- UC8. **Question intent never touches mutation plumbing.** A prompt classified as a question about the document is answered from reads; it must not open a review session, stage a suggestion surface, or force a mutating tool. The claiming test asks a question against a fixture document and asserts zero staged suggestions, zero review sessions, and an unchanged document hash — while the same fixture under an edit prompt produces a staged edit, so the test cannot pass by the channel being broken.
- UC9. **The teardown is one coordinated release.** All UC deletions ship in the same 0.5 minor with one migration note covering: `editChannel` removal, strategy/planner export removal, fallback removal, and the staleness change. Per API7 there is no deprecation window; hosts that need the XML channel pin the previous minor. A partial teardown that ships some deletions and defers others past the release boundary fails this rule (WA11).

## 3. Testing Contract

Claiming tests carry the rule ID in the test name (coverage posture: reported until claimed, per `README.md`).

- UC1: an extension-construction test asserting the AI extension exposes no `editChannel` option and mounts the tool channel unconditionally; plus a grep gate that `pen-fast-apply` survives nowhere in `packages/` source.
- UC2: the malformed-payload regression (document hash unchanged, diagnostic emitted); plus deletion of the fallback's own tests with the fallback.
- UC3: barrel-export test asserting planner symbols are gone from `@input/pen-ai`'s public API (api-report regen is the gate's artifact).
- UC4: the fingerprint tests already claiming `EC7`/`EC9` remain the authority; add one asserting no code path consults `getBlockRevision` for edit gating (grep gate on the ai package).
- UC5: the router property test over the corpus (every input → exactly one route; every union member produced at least once).
- UC6: a loop test asserting the loop's tool-forcing decision carries only the tool name; payload-shape assertions live in tool-executor tests.
- UC7: tool-server test asserting the in-editor mount list is reads + `edit_document`; document-ops tests keep covering the host-facing tools.
- UC8: the question-intent test described in the rule.
- UC9: release-mechanics, verified by the Wave 3 exit gates (changeset present, migration note present, one version bump).
