# v5 Field Editors: One Spine (FE)

Status: adopted 2026-08-26. `FE` rules are normative. They govern the editor areas of `@input/pen-dom`: the field-editor backends (EditContext, contenteditable, expanded contenteditable), gestures, frame scheduling, and table-cell editing. Selection semantics stay owned by `spec/rules/selection.md` (S1–S6) and `spec/rules/anchors.md`; `spec/rules/api.md` CS5 (selection I/O consolidation) and CS6 (the sessionReconciler rAF move) are prior tranches of the same debt this document finishes. FE changes no user-visible behavior; the conformance suites are the net for every rule here.

## 1. The Spine

- FE1. **One lifecycle spine owns attach, teardown, and listener bookkeeping.** A single module owns the field-editor lifecycle for all three backends: what attaches when a field mounts, in what order, what tears down on unmount/backend-swap, and how listeners are tracked so teardown is total. Backends register into the spine; no backend re-implements wiring. The teardown doc (`packages/rendering/dom/FIELD-EDITOR-TEARDOWN.md`) becomes the spine's document rather than a catalog of three parallel implementations.
- FE2. **A backend owns its input technology and nothing else.** Each backend module states its delta: the EditContext backend owns EditContext event plumbing; the contenteditable backend owns beforeinput/composition handling; the expanded backend (460 lines at adoption) owns only what expansion genuinely changes. Code found duplicated across two backends moves to the spine in the same PR that finds it. v4's CS5 did this for selection read/restore; FE2 extends the same rule to the full lifecycle so the next backend (if ever) is a port, not a fork.
- FE3. **The scheduler is the only raf owner in production DOM code.** No production module in `@input/pen-dom` outside `scheduler.ts` calls `requestAnimationFrame`. The four sites at adoption — `field-editor/contentGestures.ts` lines 182, 244, 1113 and `field-editor/inlineAtomWrapperInteractions.ts` line 334 — are each adjudicated: if the frame wait is real scheduling (gesture completion on next paint), it moves onto a scheduler-owned callback; if it is a selection retry in disguise, it is removed under the S4 fence, not migrated. The adjudication is recorded per site in the wave PR. A grep gate pins the end state and stays in CI so the count cannot creep back up.
- FE4. **Commits reach the scheduler.** `DomScheduler.acceptCommit` (`scheduler.ts:90`) joins the production apply path: editor commit → scheduler → reconcile under the frame budget — closing the v2 `06-dom-scheduling.md` Wave 2 gap that the conformance typing-budget scenario documents in its own annotations ("DomScheduler is not on the production apply path"). The scenario's harness-fed mode is retired in the same wave: after FE4 it measures the real path or it measures nothing. Typing-budget numbers recorded before and after are the wave's evidence that wiring the scheduler did not regress keystroke cost.
- FE5. **The gesture file splits along its three gestures.** `field-editor/contentGestures.ts` (1,143 lines at adoption — the largest file in the package) splits into pointer-selection, drag, and region-gesture modules behind the existing attach entry. No behavior change; no new concepts; the split is the mechanical precondition for FE3's adjudication of the three raf sites it contains. Gesture conformance scenarios pin behavior across the split.
  - **Shipped 2026-08-26.** Attacher is 147 lines (`GATE 4.8`). Modules: `contentGesturesPointerSelection.ts`, `contentGesturesDrag.ts`, `contentGesturesRegion.ts`, plus `contentGesturesShared.ts`. Boundary snap uses `getEditorBlockSelectionRole` rather than a block-type allowlist.

## 2. The Contracts

- FE6. **Cell editing states its parity contract.** Table-cell field editing declares, in one document with conformance coverage, which field-editor capabilities apply inside cells — marks, inline atoms, IME/composition, AI review decorations, suggestion accept/reject — and which do not. A capability outside the declared set fails closed (no-op plus diagnostic), never half-works. The recent cell suggestion-accept fix is the motivating instance: the gap was discovered by a user path, not by a stated contract; FE6 turns that class of discovery into a checklist.
- FE7. **The offset bridge is property-tested.** `field-editor/selectionBridgeOffsets.ts` (561 lines at adoption) carries the DOM↔model offset mapping — the highest-blast-radius pure logic in the spine (graphemes, inline atoms, mark boundaries). It gains property tests asserting round-trip mapping over the fixture corpus (model offset → DOM position → model offset is identity; DOM→model→DOM lands in the same rendered position), so spine refactors can lean on the bridge rather than tiptoe around it.
- FE8. **The docs follow the spine in the same wave.** `FIELD-EDITOR-BACKENDS.md` and `FIELD-EDITOR-TEARDOWN.md` are rewritten to describe the spine architecture in the wave that lands it. A structural change whose docs still describe the old structure is not done — doc drift here costs every future contributor a wrong mental model of the hardest code in the repo.

## 3. Testing Contract

- FE1/FE2: teardown-totality tests per backend through the spine (attach, exercise, teardown, assert zero leaked listeners/observers — extending the existing teardown tests to run identically against all three backends); a duplication grep recorded in the wave PR showing the moved shared code has one home.
- FE3: the raf grep gate (`rg -n 'requestAnimationFrame' packages/rendering/dom/src -g '!scheduler.ts'` over production sources returns nothing); per-site adjudication notes in the PR.
- FE4: the typing-budget conformance scenario running against the wired path with recorded before/after budgets; a test asserting commits traverse `acceptCommit` in a real editor session.
- FE5: gesture conformance scenarios green across the split; module line counts recorded in the PR (no module above the package's own hotspot bar).
- FE6: cell-parity conformance coverage for every capability the contract declares supported; a failing-closed test for one declared-unsupported capability.
- FE7: the round-trip property tests over the fixture corpus, including atom-adjacent and grapheme-cluster cases.
- FE8: review-checked in the wave PR (doc diff present alongside the structural diff).
