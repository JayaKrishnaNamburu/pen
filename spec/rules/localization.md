# Localization And Text Segmentation

Pen is headless, so every string it renders or announces belongs to the host's product rather than to the library. This document owns that copy, the locale plumbing behind formatting and comparison, and the segmentation rules that decide what a "word" and a "character" are. It governs `packages/core/src/i18n/`, `packages/core/src/editor/textSegmentation.ts`, the default schema's display copy, and every renderer, extension, and AI surface that puts text in front of a user. Hosts own translation and Pen owns being translatable: model prompts are engineering input rather than user copy and are not localized, and markdown input-rule triggers stay ASCII so bilingual users keep their muscle memory.

## LOC — Localization and text segmentation

- LOC1. All library-rendered text resolves through a message catalog — a flat map of stable, owner-namespaced keys (`pen.selection.blocksSelected`, `pen.ai.review.accept`) to strings — supplied through `messagesFacet` so extensions contribute keys and hosts override any subset without forking components. Resolution is synchronous and pure: a key and typed parameters in, a string out; Pen loads no translation files, negotiates no locales, and depends on no i18n framework, because hosts already have one. A missing key falls back to the default English catalog entry and emits a `message-missing` diagnostic once per key, never rendering the raw key to a user, and catalog completeness is checked in both directions so dead copy and missing copy both fail.
- LOC2. Block and mark `display` fields (title, description, group) and placeholders resolve through the catalog, keyed by block type, with the schema literal as the fallback; a custom schema may keep literals, since hosts defining their own blocks already own that copy. Slash-menu group headings resolve through `pen.display.group.*` entries — rendering an internal slug such as `basic` or `lists` as user-visible text is banned, because a slug is an identifier and identifiers are not copy. Placeholders follow the same path, including the document-level empty placeholder, so a localized product has no English fallbacks hiding in empty states.
- LOC3. `createEditor` accepts a BCP 47 `locale` exposed as `localeFacet`, and every `Intl.*` construction and every `localeCompare` in library code passes an explicit locale; passing `undefined` and inheriting the browser is banned, because a product shipped in Japanese to a browser set to English must format in Japanese and only the host knows which is right. When the host provides nothing, the environment locale is resolved once at editor construction and recorded, so behavior is consistent within a session. Identifier and diagnostic sorts that are not user copy pass `"en"` so they stay stable across product locales, and `Intl` formatter instances are cached per locale and options set rather than constructed in render or per cell.
- LOC4. Grapheme cluster boundaries govern character-level motion and deletion — no splitting surrogate pairs, combining marks, or emoji ZWJ sequences — and word boundaries govern word motion, word delete, double-click selection semantics, and whole-word search; both come from `Intl.Segmenter` at the editor locale through the shared helper in `packages/core/src/editor/textSegmentation.ts`. Word logic written as `\s` runs, `\b`, `\w`, or character-class ranges is banned in library code and enforced by lint, because those patterns encode "words are Latin letters separated by spaces", which is false for most of the world's text. `Intl.Segmenter` is above the declared browser floor, so it is feature-detected behind the helper: without it, word operations degrade to whitespace boundaries and character operations degrade to code points, never to UTF-16 code units, and callers never see the detection because they ask the helper for a boundary.
- LOC5. User-facing matching — menu filtering, document search, filter predicates, AI alignment checks — compares through one shared fold-and-normalize helper that applies Unicode case folding plus NFC normalization, not `toLowerCase()`; the Turkish dotless `ı` and the Greek final sigma are the standard failures and both are silent wrong answers rather than crashes. One helper owns fold-and-normalize so search, filters, and menus can never disagree about whether a query matches. Case-sensitive search stays exact and skips folding entirely, so the toggle means what it says.
- LOC6. Any string containing a count is a single catalog entry with CLDR plural categories (`zero`, `one`, `two`, `few`, `many`, `other`) selected through `Intl.PluralRules` at the editor locale; English's two-form rule is not the model, and a counted phrase assembled at the call site is a bug. Composed sentences are one catalog entry with named parameters rather than fragments joined in code, since word order differs between languages and a fragment cannot be translated without its sentence. Interpolated user content is passed as a parameter whose entry documents its direction handling so right-to-left content inside a left-to-right sentence does not scramble, and screen-reader announcements are catalog entries like any other string.

## Retired

No `LOC` member is retired. LOC1–LOC6 are all live and govern shipped code.
