# AI Boundary

Pen ships no vendor SDK and makes no network call of its own: model access goes through a `ModelAdapter` the host injects, and transports go through `PenTransport`. This document owns the contract across that boundary — what document content leaves the browser and under whose control, what a model-driven tool may do to a document, how an AI action appears to undo, how the stream protocol evolves, and how a host tests any of it. It governs `packages/extensions/ai` and its subpaths, `packages/extensions/document-ops`, the stream and tool contracts in `packages/types`, `packages/transports/sse`, and the model doubles in `packages/tooling/test`. The edit-channel rules (the EC family, covering how a durable AI edit is encoded and applied) live with the package they govern, in `spec/packages/extensions/ai.md`.

## AIB — AI boundary

- AIB1. Every request Pen assembles passes through one egress facet — `pen.aiEgress`, resolved through `aiEgressFacet` in `@input/pen-core` and re-exported by the AI package — before it reaches a `ModelAdapter`, carrying a structured `AIRequestContext` of feature, messages, per-block document excerpts tagged `selection`, `target`, `context`, or `tool-result`, and tool schemas, rather than a pre-rendered prompt string, because a host redacting content needs to know which text is document content and which block it came from. Returning `null` cancels the request with an `ai-request-refused` diagnostic and no model call: a refusal is a normal outcome that reports the feature as unavailable for that invocation and leaves the editor running, not an error. Every AI feature routes through the facet, including autocomplete and proactive suggestions, since the host that needs redaction needs it most on the feature that fires every few keystrokes, and the filter is synchronous and cheap — asynchronous review belongs in the host's `ModelAdapter`, which is already where network work lives.
- AIB2. One published table, generated from the exported constants rather than written by hand, states for every AI feature what document content it includes, the maximum characters it will send, and what triggers it, because a host's privacy review is a real document that someone signs and today it would need a code reading. Every bound is a named exported constant with a default that the AI extension's config can override, and nothing sends unbounded document text, including the agentic working set; tool results that re-enter a prompt are excerpts like any other content, under the same table, the same caps, and the same egress facet, because that is the path that grows silently as each step's output becomes the next step's input. `PenStreamRequest.context` carries no `editor` field — a field typed `unknown` on a serialized request is an invitation to send the editor instance to a server, and `unknown` means the compiler cannot decline — but the explicit serializable subset instead, and the docs state the thing hosts most need and cannot infer: Pen sends nothing anywhere on its own, and every byte in the table travels only through the adapter the host wrote to the endpoint the host chose.
- AIB3. Tool availability is a host-controlled allowlist resolved as a facet, defaulting to the tools the enabled extensions register, so a host shipping AI reading but not AI writing expresses that in one line rather than by not installing a package other features need. Destructive tools declare themselves with a `destructive` flag on the tool descriptor and pass through a confirmation seam — a host-provided resolver that may allow, refuse, or defer; absent a resolver the default is allow with a diagnostic, and a deferral is an answer that blocks the call and must not also take the allow-with-diagnostic path. Budgets are declared, defaulted as named constants, and enforced by the loop — model passes per run, tool calls per turn, document ops per call and per turn, and a wall-clock deadline — and exceeding any budget ends the run with a reported reason rather than an exception, leaving the partial result in whatever review or suggestion surface the run was writing to; Pen does not meter tokens or cost, because the adapter owns the model call and an invented estimate is a number hosts would trust. Every mutation a tool makes stays an `editor.apply` through the standard pipeline with a tool-attributed origin, so validation, normalization, and suggest mode still apply — tool authority is about whether, never about bypassing — and because the tool-execution sink is reachable without a grant from in-process host callers, adding a caller of the tool executor or the validated-op applier is a security change reviewed as one.
- AIB4. An AI action — one generation, one accepted suggestion, one agentic run — is one undo step for the user, where the unit is the action the user asked for and not the number of ops it took. The group identifier is created once where the action starts and threaded through every write the action performs, including tool applies, streamed block ops, and host-driven streams, so an AI write path that cannot name its group is a bug in that path; capture-timeout manipulation is removed in favor of explicit grouping rather than kept alongside it, because keeping both makes the boundaries depend on timing. A run the user cancels mid-flight is still one undo step covering what landed before the cancel, since partial results the user can see must be reversible in one action, and the documented limit is that undo is per-client: undoing an AI action reverts this client's ops and cannot revert a collaborator's interleaved edits.
- AIB5. The stream protocol carries a version (`PEN_STREAM_PROTOCOL_VERSION`), the consumer checks it, and a mismatch is a diagnostic and a refused stream rather than a partially applied document. Part handling is exhaustive: the part `switch` ends in a `never` check so a member added to the union without a handler fails the build, no inbound member is left silently inert, and unknown parts from a newer server are dropped with a `stream-part-unknown` diagnostic once per part type per stream, because silently ignoring a part is how a host spends an afternoon debugging a document that never changes. Known parts are validated before they reach the document — required fields present and correctly typed, ids non-empty, ops built from validated fields — and the consumer degrades rather than asserts, treating a missing streaming target as a diagnostic and a refused stream instead of a non-null assertion; the wire format is documented as a wire format (parts, fields, ordering rules, and version policy) because a host writing a server implements it from documentation.
- AIB6. `@input/pen-test` exports a scripted mock `ModelAdapter` and a stream fixture builder driven by a declared sequence of parts, with controls for delay, abort mid-stream, error parts, and malformed parts, so a host can test its AI integration without a model and without a network. The mock is the same one Pen's own suites use, because a fixture only the library's tests exercise drifts from the shapes hosts actually receive, which is the failure this rule exists to prevent. It observes the egress facet and the tool budgets so a host can exercise its own redaction filter and its own tool allowlist offline, and two fixtures ship as documented examples because they are the cases hosts get wrong: a generation stream that aborts halfway, and a tool call that fails.
- AIB7. Playground-specific planners and context builders are not public API: they are marked internal and stripped from the published type declarations, or they move into `playground/`. The reason is not tidiness — they are the most copy-pasteable thing in the package, so a host looking for "how do I build a request" finds them and inherits a demo's truncation limits and egress posture as production architecture. What replaces them is the documented integration path — a `ModelAdapter`, the egress facet, and the mock adapter for tests — plus the AI example, enforced by the published API report so there is one supported route rather than an accidental one.

## Retired

No `AIB` member is retired. AIB1–AIB7 are all live. One surface element was removed rather than a rule: the `editor` field left `PenStreamRequest.context` under AIB2 and is kept out by a gate.
