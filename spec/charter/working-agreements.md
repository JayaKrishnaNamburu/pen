# Working Agreements

How a spec train is written and executed. These are process rules, not product rules: they govern the documents and the PRs, not the editor's behavior. `coverage-rules.mjs` lists `WA` in `PROCESS_PREFIXES`, so no `WA` rule carries a test-name obligation.

WA1–WA10 accumulated across the redesign, distillation, scaffolding, and edit-channel trains. Each one exists because the repository paid for its absence once; the incident is kept with the rule, because a process rule without its story gets optimized away by someone who never saw the failure. An executing train inherits these unchanged and may add its own numbered agreements.

## The Agreements

- WA1. **The spec set is closed.** A train is its numbered documents plus one work order per wave, written before execution and complete enough that no implementation decision is left open. New documents are prohibited; when implementation proves a rule wrong, the existing document is amended in the same PR. Silent divergence between code and spec is never acceptable.
- WA2. **Status is computed, never narrated.** Gates are machine-extractable `- GATE` lines in the wave files, executed by the gate runner locally and in CI. Wave files contain no status prose. An earlier train's wave files accumulated contradictory status paragraphs — "not started" eight lines above the checkpoint saying it was done — and the fix is structural rather than editorial: there is nowhere to write status, so it cannot drift. This agreement is dormant between trains: the runner and the scope-lint gate that classified those lines were deleted with the v5 train, because both took a train's `waves/*.md` as their only input, so the next train reintroduces them along with its wave files. Two of the runner's habits are worth carrying in by hand until it exists again — a gate that cannot fail is a defect of the PR that wrote it, and a gate whose command was never executed as written is not a gate.
- WA3. **A mechanism and its first consumer land in the same wave.** The DOM scheduler shipped two waves before anything called it, and the budgets committed alongside it measured an unwired loop. Never ship a slot without its occupant.
- WA4. **Standing gates, not waves.** Security, code health, accessibility, and performance budgets are permanent CI gates. A train adds none of them to its critical path and none of them to its release gate, because a standing gate that blocks a wave stops being a standing gate.
- WA5. **Break honestly, with users.** Every deletion lands with a migration recipe in the same PR (`spec/rules/api.md` API7). No runtime deprecation adapters: adapters written for nobody are a cost with no beneficiary.
- WA6. **Name the native capability before borrowing.** Any design adopted from prior art must state what the underlying platform — the CRDT, the DOM, the language — already provides for the same problem, and why it is insufficient. The position-mapping algebra existed for a year because nobody wrote the sentence "Yjs already has relative positions." This agreement makes that sentence mandatory.
- WA7. **An instrument is amended in the PR that deletes its subject.** Gates, allowlists, globs, sink lists, and coverage claims are part of a deletion's blast radius. Leaving an instrument red for the wrong reason, or green over nothing, is a defect of the deleting PR rather than cleanup for later. A gate whose subject is gone is amended with a dated correction, not deleted — a deleted gate cannot catch the subject's return.
- WA8. **No redesign under the broom.** A consolidation wave may move, merge, rename, retype, and delete; it may not change observable behavior. The proof obligation is mechanical: the conformance suite and every package's public API report pass unmodified, except where a rule in the executing set names the change. An improvement idea discovered mid-wave is recorded for a future train, not smuggled into this one.
- WA9. **A lane reports failures outside its fence; it does not attribute them.** A fence gives a lane authority over its own files and no visibility into anyone else's, so "another lane did it" is the one explanation that is always available and never checkable from inside. It is therefore the explanation a lane reaches for, and it is worth nothing. Measured: three lanes independently reported the same `@input/pen-ai` router failure and each attributed it to a concurrent AI lane. No AI lane existed; the cause was uncommitted work on the agentic loop correcting `maxSteps` to bound model passes rather than step entries, which grow twice per tool call. The lanes were right that it was not their fence and wrong about everything else, and the error was invisible because a plausible attribution reads exactly like an investigated one. Two obligations follow. Report the failing package, test, and assertion, and stop there, because attribution belongs to whoever can see every fence. And treat a repo-wide test run from inside a lane as provisional, because turbo's `dist/` and cache are shared, so a lane's full-repo result measures a tree other lanes are actively rebuilding — re-run the failing package alone, and if it is green in isolation but red under concurrency, that is a shared-artifact effect rather than a code defect.
- WA10. **A prototype states the measurement that would kill it, before it is built.** The failure this prevents is one this repository has already paid for: a channel borrowed from a system whose central mechanism was left behind, adopted because the shape looked right, and never measured against the thing it replaced. A prototype whose only exit is adoption is not evidence — it is a commitment wearing an experiment's costume. The corpus, the metrics, and the losing threshold are written into the wave file before the first line of the prototype, and a negative result is a valid, recordable outcome that closes the set.

## Amendments

An agreement is amended in place with a dated note rather than renumbered, on the same reasoning as `spec/charter/rule-ids.md`: a citation must keep resolving to the rule it named. A train that gives an inherited agreement extra force for its own duration says so in its own concept document instead of editing the text here.
